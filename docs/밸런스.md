# 밸런스

숫자를 정하는 **원칙**. 숫자 자체의 원본은 `data/*.js`이고, 여기엔 숫자를 고를 때 지킬 기준만 적는다. 숫자를 바꾸면 `node tools/balance.js`로 원칙에 맞는지 확인한다(→ 5). 게임 규칙은 → `기획.md`.

## 1. 자원 고리
```
 돈 ──(씨앗값)──▶ 씨앗 ──(심기)──▶ 밭
  ▲                                │
(요리값)                      (자라는 기간)
  │                                ▼
 손님 ◀──(손질 · 아내 기력)── 아내 ◀──(나르기 · 가방)── 수확
```
고리의 화살표마다 숫자가 하나씩 붙고, 원칙도 화살표에 붙는다(→ 3). 도구는 고리의 한 화살표를 빠르게 한다.

## 2. 시간은 두 가지
- **날짜 시간**: 작물이 자라는 며칠. 기다림
- **하루 시간**: 오늘 쓸 수 있는 시간(오전 8시 ~ 오후 3시). 캐기 · 심기 · 작업대에 건네기 · 가게 다녀오기가 정해진 분만큼 빠져나간다(걷기는 0, 이동은 행동에 포함). 아내의 장사도 같은 시계(→ `기획.md` 4). 하루 장사 한도(아내의 기력)는 시간과 따로(→ `기획.md` 5)
- 「돈으로 시간을 산다」(→ `기획.md` 5)는 하루 시간 쪽 이야기다

## 3. 화살표마다 원칙
기준 숫자에 근거가 없는 것은 **추측**이라고 적는다. 해 보고 맞춘다.

| 화살표 | 숫자(원본) | 원칙 |
|---|---|---|
| 씨앗값 · 요리값 · 자라는 기간 | `data/crops.js` | **작물끼리 공평하게**: 칸 하나가 하루에 버는 돈 `(요리값 − 씨앗값) ÷ 자라는 기간`이 작물마다 비슷하다(차이 20% 안, 추측). 안 그러면 한 작물만 심는다. 오래 걸리면 그만큼 비싸게 |
| 하루 시간(캐기 · 심기 · 건네기 · 가게) | `data/day.js` | **초반 하루가 꽉 찬다**: 초반 하루 일을 다 하면 오후 2~3시(→ `기획.md` 2) |
| 나르기 ↔ 손질 | `data/config.js` 가방 · `data/crops.js` 손질 · `data/day.js` | **핵심 리듬**: 한 번 나르는 시간 ≈ 가방만큼 손질하는 시간(차이 30% 안, 추측)(→ `기획.md` 5) |
| 처음 가진 것(돈 · 씨앗 · 첫날 밭) | `data/tutorial.js` | **튜토리얼 동안 고리를 한 바퀴**: 모든 작물을 한 번씩 캐 보고 심어 볼 수 있다 |
| 일꾼(중반) | 아직 없음 | **바깥 일꾼은 자기가 먹는 것보다 많이 구해 온다.** 안 그러면 들일 이유가 없다(→ `기획.md` 5 일꾼) |
| 지나가는 사람 수 | 아직 없음 | **초반엔 지나가는 사람이 모자라지 않는다.** 막는 건 재료와 아내의 기력뿐. 사람 수가 막으면 열심히 할수록 손해가 된다(옛 규칙의 「손님 6명 병목」 → 4). 사람 수는 나중에 길이 자라며(→ `기획.md` 5 동네) 느는 성장으로 쓴다 |
| 쉬는 날 버프 | 아직 없음 | **버프로 얻는 것 > 쉰 하루, 조금만.** 쉬는 게 손해가 아니라 현명한 선택이 되게. 너무 크면 쉬는 게 정답이 된다(→ `기획.md` 4) |
| 도구 값 | `data/town.js` | **며칠 장사하면 하나**: 값 = 하루 벌이의 2~3일치(추측) |
| 자라는 기간 | `data/crops.js` | **초반엔 빈 날 없음**: 가장 짧은 작물은 하루 만에 자란다. 너무 짧아도 농사의 맛이 없다(→ `기획.md` 5) |
| 아내의 기력 | `data/customers.js`(옛 손님 수, 바꿀 것) | **하루 장사량 한계**: 식당은 갖다준 재료만큼, 아내의 기력까지만 판다(→ `기획.md` 5). **다시 볼 것**: 원칙을 새로 정한다 — 후보(추측): 초반 한도는 하루 시간을 다 써서 구할 양보다 작게, 남은 시간이 생산적인 일로 가게 |

## 4. 지금 알게 된 것
- 아래는 저녁 직접 서빙(손님 6명) 기준으로 따진 것. 식당이 자동 + 아내의 기력 한도로 바뀌어(→ `기획.md` 4 · 5) 다시 따져 본다. 「밭으로 하루를 못 채움」은 남은 시간이 생산적인 일로 가며 문제가 아니게 될 수 있다(추측)
- 손님 6명이 병목이라, 밭을 꽉 채워 바쁘게 일할수록 손해였다(이익이 가장 큰 조합은 밭을 덜 채우고 오전 10시 반에 끝남)
- 손님만 늘리면 배추만 잔뜩 심는 게 정답이 된다 — 시간이 드는 건 「행동」인데 배추는 3일에 한 번만 손이 가고 비싸서, 같은 시간을 들였을 때 배추가 훨씬 번다. 원칙 「작물끼리 공평하게」는 날짜가 아니라 **들인 행동 시간당** 이익으로 봐야 할 수 있다
- 밭 16칸으로는 하루를 채울 만큼 행동이 안 생긴다 → 하루를 무엇으로 채울지(→ `기획.md` 5 재료는 노력과 시간)가 먼저 정해져야 숫자를 맞출 수 있다. 그때까지 밸런스는 멈춤
- 초반엔 단순한 방식이 곧 최적이어야 한다(누구나 해낼 수 있게). 깊은 최적화는 중반 이후의 재미

## 5. 계산 도구
걷기에 시간이 안 들어서 계산과 실제가 같다. 모두 `data/*.js`를 읽는다.
- `node tools/balance.js` — 3의 원칙마다 지금 숫자를 어림해 맞으면 ✓, 벗어나면 ⚠
- `node tools/simulate.js [며칠] [난수]` — 튜토리얼부터 게임 규칙대로 자동 플레이(씨앗 · 도구 사기 포함), 날마다 끝난 시각 · 손님 · 돈
- `node tools/combos.js [며칠]` — 빈 밭에서 「작물마다 몇 칸」 조합을 전부(16칸이면 969가지) 돌려, 원칙에 맞는 조합 · 이익 높은 조합 · 끝나는 시각 분포
