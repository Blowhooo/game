# 아트 규격

그림 · 판정의 크기 기준, 누가 무엇을 뽑는지, 그림에 대해 배운 것. 그림(에셋)은 이 규격에 맞춰 새로 뽑고, 코드는 규격과 데이터만 읽는다(→ `기술.md` 1).

## 1. 세 가지 크기를 따로 정한다
| 개념 | 뜻 |
|---|---|
| **격자(타일)** | 맵의 기본 칸. 땅 상태 · 물건 놓는 자리 · 이동 판정의 기준. **16×16** |
| **그림(스프라이트)** | 화면에 그리는 크기. 격자보다 커도 되고, 넘치는 쪽은 **위**. |
| **차지하는 자리(풋프린트) · 판정(히트박스)** | 실제로 바닥을 차지하고 부딪히는 면적. 그림보다 작고 **발밑 · 밑동**만. |

모든 것을 같은 크기(32×32)로 그리면 사람과 물건이 똑같아 보여 어색하고, 물건 그림만 줄이면 판정이 애매해진다 → 그림과 판정을 분리한다(스타듀 밸리가 쓰는 원리).

## 2. 종류별 기본값
| 종류 | 그림 | 차지하는 자리 | 예 |
|---|---|---|---|
| 사람 | 16×32 (필요하면 가로 24까지) | 발밑 1칸, 판정은 그보다 조금 작게 | 부부 · 손님 |
| 작은 물건 | 16×16 | 1칸 | 돌 · 자루 · 음식 아이콘 |
| 키 큰 물건 | 16×32 | 바닥 1칸 | 작물 · 상자 · 등불 · 간판 |
| 나무 | 32×48 ~ 48×80 | 밑동 1~2칸 | |
| 건물 | 격자의 배수 | 바닥 몇 칸(문 자리는 비움) | 식당 · 창고 |

- **기준점**: 그림의 아래 가운데(발 · 밑동)를 칸에 맞춘다.
- **그리는 순서**: 바닥(기준점)의 y가 작은 것부터 → 앞에 선 것이 위에 그려진다(나무 뒤로 가면 가려짐).
- **시점**: 탑다운 3/4(위에서 비스듬히). 모든 그림이 같은 시점.
- **화면 배율**: 정수 배율(픽셀이 흐려지지 않게). 몇 배인지는 화면 크기와 손가락 크기로 정해진다(→ `기술.md` 1).

## 3. 예외는 데이터로
물건마다 크기를 데이터에 적고, 없으면 종류 기본값을 쓴다. 코드는 숫자만 읽는다 — "이 물건이면" 하고 코드로 골라 처리하지 않는다.
```js
tall: { sprite: [16, 32], footprint: [1, 1] },                                   // 종류 기본값
scarecrow: { kind: 'tall' },                                                       // 그대로
pumpkin_giant: { kind: 'tall', sprite: [32, 32], footprint: [2, 2] },             // 이 물건만 크게
well: { kind: 'building', sprite: [32, 48], footprint: [2, 1], hitbox: [2, 4, 28, 12] }, // 판정 직접 지정
```
코드를 고치는 건 **새로운 행동**(움직이는 장애물 · 올라타기 등)이 생길 때뿐. 그때도 그 물건 전용이 아니라 기능 하나를 만들고 데이터로 켠다.

## 4. 누가 무엇을 뽑나
- **캐릭터 · 동작 = PixelLab, 사용자가 직접**(크레딧은 캐릭터에만). 크기 32로 만들면 32×32 캔버스 안에 사람 → 16×32에 맞춰 자른다. Claude는 받은 PNG를 데이터로 바꿔 붙인다.
- **사물 · 환경 = Retro Diffusion, Claude가**: 타일 · 작물 · 아이템 · 나무 · 건물 · UI · 이펙트. 타일은 16, 물건은 2의 표 크기로 지정. PixelLab으로 사물을 뽑지 않는다.
- **인물 원화 · 대화창 얼굴 = 제미나이, 사용자가 직접.** 인물마다 기본 그림(전신 · 평온한 얼굴) 한 장으로 생김새를 확정 → 그 그림을 기준으로 표정(상반신)을 한 장에 모아 뽑는다. 그림체를 맞추려고 공통 문구를 매번 앞에 붙인다
  - 원화 비율은 5등신쯤(첫 주인공 그림 기준). 게임 속 픽셀 인물(16×32)은 따로 줄여 그린다
  - 표정은 한 장에 3개(1×3) — 6개를 한 장에 넣으니 전신으로 그려져 얼굴이 너무 작았다. 얼굴만(상반신) 뽑으면 얼굴이 갸름 · 젊게 바뀌었다(주인공) → 허리 위(어깨 · 배까지) + 「같은 얼굴(둥근 얼굴 · 나이 · 수염) 유지」 문장을 넣어 다시 볼 것
  - 표정은 모든 인물을 같은 기본 12가지로 미리 다 뽑아 두고(사용자 결정), 인물마다 몇 가지를 더한다
    | 인물 | 표정 |
    |---|---|
    | 공통(모두, 12) | 기본 · 미소 · 크게 웃음 · 화남 · 짜증 · 슬픔 · 울음 · 놀람 · 당황 · 부끄러움 · 걱정 · 생각 |
    | 주인공 | 귀찮음(한숨) · 멋쩍음 |
    | 아내 | 웃는데 긁힘(입은 웃고 눈은 안 웃음) · 환해짐 · 피곤함(임신 후반) |
    | A | 반짝 자신만만 · 울먹 감동 · 허둥 |
    | 종묘상 · 대장장이 | 신나서 떠듦 |
- 도구 사용법 · 가격은 → `기술.md` 2.

## 5. 배운 것
- **캐릭터 동작**: PixelLab이 확실히 잘함(뼈대 동작 틀). 다만 template 동작은 캐릭터를 새로 그려 얼굴 · 크기가 바뀜(skeleton 방식은 유지되지만 움직임이 작음). Retro Diffusion 동작은 캐릭터 유지는 좋지만 팔다리 · 도구 · 무게중심이 엉성하고, 발을 크게 그려 탑다운 시점이 깨지기도 함. Claude가 픽셀 조각을 옮겨 붙여 고치면 갈수록 깨짐.
- **Retro Diffusion이 잘하는 것**: 경계가 이어지는 타일셋 · 타일 위 물건 · 아이템 모음 · UI · 이펙트 · 배경 · 잔잔한 움직임(작물 흔들림).
- **도구 · 물건 요청**: 이름만 쓰면 무기 · 판타지 물건으로 그림(괭이 → 전투용 낫). 직업 · 세계관에 맞는 생활 도구로, 모양 · 재질 · 크기 · "무엇이 아닌지"까지 적는다. 쓸 때 · 들고 다닐 때 쥐는 손(한 손 · 두 손)도 따로.
- **타일셋을 여러 벌 뽑으면 잔디 색이 벌마다 다르다**(잔디↔밭 · 잔디↔길을 따로 뽑으니 하나는 탁한 초록, 하나는 밝은 연두) → 기준 잔디 한 칸을 잘라 `rd_tile__tileset_advanced`의 그림으로 넣어 다시 뽑으면 거의 맞고, 남는 미세한 차이는 타일셋의 잔디를 투명으로 해 없앤다(→ `기술.md` 3 `art_to_js.py`).
- **밭 흙**: 「tilled soil」만 쓰면 벽돌 무늬가 나온다 → 「부드러운 흙 · 가로 이랑 · 벽돌 아님 · 돌 아님」처럼 무엇이 아닌지까지 적는다. 그래도 이랑 줄무늬는 아직 약하다.
- **색**: 환경 그림을 Resurrect 64로 맞추면 잔디가 청록, 흙이 붉게 탁해짐 → 원래 색 그대로 쓴다.
